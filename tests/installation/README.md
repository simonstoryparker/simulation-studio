# Native installation and update acceptance

Run the **Installer and updater acceptance** workflow with a draft release tag. It downloads and verifies the original platform artifacts from the successful release build (using read-only Actions access), installs them on native macOS and Windows runners, and tests manual replacement and a real Tauri update to the draft release. Results and logs are uploaded as workflow artifacts. No private robot repository or updater private key is needed.

`prepare.mjs` generates a disposable 0.0.0 copy of Studio. Only that copy receives a loopback HTTP feed and the Rust driver; the production source, HTTPS feed, and signature checks are unchanged. The driver invokes Studio's existing download, preparation, persistence and installation code. The test compares the updated executable’s hash with the executable installed from the production installer. The public release key verifies the real updater signature.

`run.mjs` tests paths with spaces, installer re-runs, preserved layouts/controller profiles, failed checks, interrupted/tampered downloads, connection deferral, reconnect blocking, clearing enabled/held-input state, removal of a resource that existed only in the old package, and production relaunch using the latest session. A loopback control fixture inspects the restarted app's outgoing frames. This covers an upgrade from the generated older copy to the production release. Upgrades from other historical versions need separate testing.

Runner automation does not establish first-download Gatekeeper/SmartScreen approval, hardware controller behavior, or physical clean-machine compatibility. These remain manual platform checks. Local macOS runs install into a disposable directory; the normal installed app must be closed because Studio enforces a single instance across installations.
